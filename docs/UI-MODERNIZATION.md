# LocalPM UI/UX V1.0 implementation and acceptance

Implementation branch: `dev`. Design baseline: the supplied LocalPM UI/UX modernization specification. Existing uncommitted MCP/backend/release changes were present before this task and are outside this UI change.

## Audit and scope

The frontend uses React, Zustand, i18next, plain CSS semantic theme variables and CodeMirror. Tauri provides HTTP execution, SQLite persistence, OS credentials and request-boundary diagnostic events. The existing `ConsolePanel` already supports filters, request/response previews, proxy/TLS/timeout metadata and resizers. Those capabilities and their data policy were retained.

The principal gaps were small interaction text, inconsistent theme surfaces, a narrow Console maximum (`window height - 500`), no persisted Console open state, a fixed editor default, and resource panels unmounting whenever the resource category changed. Collection expansion state was local to the unmounted tree. The expansion button's accessible label also described the opposite action. These were corrected by retaining the resource panel instances and correcting the state/label relationship, rather than changing stacking order.

## Final automated acceptance

- Production TypeScript/Vite build and ESLint pass.
- 12 Vitest tests pass.
- 33 Playwright tests pass, including real Rust HTTP/SQLite execution and restart, MCP concurrency/cancellation, and the 10,000-item bounded tree test.
- Window matrix: 900×640 (existing minimum), 1280×800, 1440×900 and 1920×1080; both English and Chinese in both themes.
- A 1440×900 viewport at device pixel ratio 2 validates resource navigation, response controls and expanded diagnostic details.
- Native Tauri window decorations are retained; macOS traffic-light controls remain outside the web content. No release workflow, application version, collection/environment schema or request engine was changed for this task.

Screenshots are generated by test fixtures. They demonstrate layout, not production network results. The production UI continues to show results returned by the request execution layer. Useful artifacts: `artifacts/modern-ui-retina.png`, `artifacts/modern-ui-dark-zh-CN.png`, `artifacts/modern-ui-light-en-US.png` and `artifacts/workspace-minimum-console.png`.

The Vite build retains a main-chunk size warning (>500kB) from the Motion-based UI integration. No new UI framework was added. Browser high DPI and theme tests do not substitute for native Windows/macOS platform acceptance; those remain explicit follow-up verification items.

## Interaction correction after native trial (2026-10-11)

The previous acceptance over-emphasized visibility and scripted functional execution. It incorrectly encoded typed method editing, hidden single-request tabs and collapsed resource entry points as expected behavior. The following changes supersede those choices:

- HTTP method is a real native `select`, with GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS/CONNECT/TRACE. Custom methods use a separate, explicit editor and token validation; partial typing never changes the request method.
- Application toolbar no longer contains a request creation button, request-name textbox or collection-only search button. Collection search stays in the resource panel, with the existing keyboard shortcut.
- The workbench tab strip is always visible, including for a single request. Its New request action creates a temporary draft. Request name, location and Save are located in the request builder.
- Each collection/folder has an Add request action. This immediately creates the request at the specified location; subsequent sidebar selection cannot redirect it.
- Saving a temporary request opens an explicit collection/folder destination chooser. No automatic fallback to the first collection. Sending a temporary request no longer inserts it into a collection. Collection edits retain local drafts; only explicit Save updates the saved request. Send uses the current draft and preserves authentication inheritance.
- Selecting a request tab synchronizes the resource highlight and restores its configuration section. Configuration tabs select sections; collapsing is a separate control with an up/down chevron.
- Console has a stable workspace status-bar entry rather than being hidden in request actions. Expansion reserves space for useful request editing, with extra limits at the existing minimum window size.

Validation: 38 Playwright tests pass, including five new task-based acceptance checks for real method selection, explicit custom-method confirmation, temporary sending without collection insertion, explicit save destinations, folder-scoped creation, entry-point scope and tab/resource synchronization. Existing Rust HTTP/SQLite, MCP, internationalization, window-size and 2× DPI tests remain passing. Build, lint, 12 Vitest tests and `git diff --check` pass.

macOS native inspection used a separately identified copy of the built app with `LOCAL_POSTMAN_DATA_DIR=/tmp/localpm-ui-acceptance-data`, so the user's running app and workspace were not edited. The accessibility tree confirms an HTTP-method popup and its GET/POST/etc. menu, and the workbench/resource/save/Console entry points. Native automation did not confirm a value change after attempted menu selection; the native selection interaction remains a manual acceptance item. Browser selection and resulting method changes were verified by tests. Windows native selection remains unverified.

The corrected Apple Silicon package is `artifacts/LocalPM-0.5.0-macos-arm64-ui-interactions.dmg`. Both app signature verification and DMG checksum verification pass. It retains local ad-hoc signing and is not Apple-notarized.
